# Complete-image loading and WebP display

The shared root `ImageLoading` controller applies to public pages, dashboard pages and dynamically inserted rich-text images. It keeps the existing image element and event handlers, displays an opaque shimmer in that image's bounds and reveals it only after load plus `HTMLImageElement.decode()` completes. It ignores stale completions when a source changes, handles cached images, replaces failed images cleanly, respects reduced motion and provides a no-JavaScript opacity fallback. Fixed artwork frames retain their dimensions; unmeasured images reserve a provisional area until natural dimensions are known. Existing cropping is preserved, so an intentional card crop is separate from progressive download painting.

Own uploaded JPEG/PNG/AVIF/static GIF images use a presentation-only `/api/image-display?file=/uploads/...` URL in the browser. The API handles local upload files only, encodes a cached WebP variant with alpha/EXIF rotation support, varies by Accept and retains the original for unsupported browsers or unavailable conversion. It runs through the API because the production Apache/Passenger setup may serve physical `/uploads` paths without Express. Existing upload GETs also negotiate WebP when handled by Express; original social URLs retain JPEG for Meta. Encoding is serialized and duplicate requests share a pending job. Cache keys include the source size/mtime, and the existing opt-in social retention purge also removes its current WebP variants.

The database media URL and publishing payload remain original. A display URL is never saved as an Instagram publishing URL. SVG logos, animated files, favicon/manifest assets and third-party provider images keep their appropriate existing formats. No remote image proxy is introduced. If sharp or a filesystem operation is unavailable, the original image remains usable; do not label such a response WebP without checking its actual Content-Type.

Validation includes real local HTTP/content-type/byte checks for negotiation, alpha, animation, source changes, social original-byte retention, cache cleanup, HEAD requests and rejection of remote/traversal paths. Browser checks deliberately delay downloads and decoding, replace a source before an older decode completes, exercise failures/replacement and verify mobile layout. Report prototypes remain separate, sample-data-only design artifacts.
